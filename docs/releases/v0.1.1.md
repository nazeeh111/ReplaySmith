# ReplaySmith v0.1.1

Native recordings from real websites now retain consistent target evidence through replay and both exported formats. This release fixes failures reproduced on TodoMVC, The Internet, and the Python and Playwright documentation sites.

## Changes

- Share semantic evidence extraction across recording, replay and exported scripts, including nested heading context, labels, unnamed dropdowns and native control defaults.
- Capture picked outcomes on pointer press before page mouse handlers can replace the target, with a keyboard/synthetic click fallback. Show capture acknowledgement and wait for outstanding captures before Stop, including rejected-capture error paths.
- Wait for asynchronously enabled/editable controls within the configured budget, while rechecking identity, origins and consequential-action permissions before acting once.
- Preserve native heading level during semantic recovery; require identifying evidence beyond heading level; refuse wrong-level or ambiguous headings and incomplete candidate scans. Batch visible-candidate evidence into one browser round trip using Playwright visibility filtering.
- Compare normalized DOM text consistently, including hidden descendant text such as documentation permalink markers.
- Add `--timeout-ms` to the CLI and both exported scripts: 100–60000 ms, default 5000. The public-site suite uses 15000 ms explicitly.
- Add an opt-in, reproducible live acceptance suite and publish the specific tasks, observations, baseline failures and limits.

Confidence and ambiguity thresholds remain unchanged. Old recordings with inconsistent evidence should be re-recorded and reviewed. Strict Content Security Policy sites remain supported without enabling unsafe page-side evaluation.

## Verified evidence

Eight workflows across five public websites passed native recording, preparation, replay and outcome checks; 22 actual Playwright/Agent Skill export processes verified their outcomes. Three navigation workflows also recovered from local layout changes and stale exported selectors. Three fresh documentation recordings captured their final assertions.

The canonical 132-trial benchmark uses the same normal 5000 ms budget for every policy. ReplaySmith verified 15/15 supported changed-page trials, safely abstained on 12/12 refusal trials, rejected all corrupted outcomes and took zero incorrect actions. The earlier failed 900 ms run is preserved publicly and explained in the report.

There are 51 regression cases. The complete local run had six short-budget failures, all of which passed an isolated recheck without changing budgets; this is not described as a full local pass. Complete Node 22/24 CI is required for stable publication. A fresh consumer installation of the exact tarball passed the installed CLI, browser installer, studio, outcome verification, unverified exit-code checks and both generated exports.

See [public website checks](../real-websites.md), [controlled benchmark](../benchmarks.md) and [release validation](../validation.md). These are bounded, developer-authored checks; passing them does not establish arbitrary-site reliability.

## Install

```sh
npm install --global https://github.com/nazeeh111/ReplaySmith/releases/download/v0.1.1/replaysmith-0.1.1.tgz
replaysmith install-browser
replaysmith studio
```

The package is distributed through this GitHub release, not the npm registry. Node 22+ is required. Both generated scripts accept `--timeout-ms 15000` for slower pages. Existing single-origin, single-tab restrictions and consequential-action safeguards continue to apply.
